# Исследование: «ключа нет» против «значение `null`»

**Дата:** 2026-10-10 (UTC). **Статус:** решено 2026-10-11 (UTC) — вариант A.

## 1. Где различие важно

| Схема свойства | Сейчас | Чего теряем |
|---|---|---|
| в `required`, не nullable | `T`, без default | ничего |
| в `required`, nullable (`type: [T, 'null']`) | `?T`, без default | ничего: ключ обязан быть |
| не в `required`, не nullable | `?T = null` | **`null` проходит**, хотя схема его запрещает: «нет ключа» и «`null`» склеены в одно значение |
| не в `required`, nullable | `?T = null` | **нельзя отличить** «не прислали» от «прислали `null`» |

Практические случаи:

- **PATCH / JSON Merge Patch (RFC 7396).** `{"nickname": null}` — стереть, отсутствие ключа — не трогать.
  С текущими DTO обработчик не может реализовать merge-patch без сырого массива.
- **Частичные ответы** (`fields=`): отсутствие ключа ≠ значение `null`.
- **Валидация.** Строка 3: `{"nickname": null}` должна отклоняться, а сейчас проходит.
- **Сериализация обратно.** Ответ с `"nickname": null` вместо отсутствующего ключа меняет контракт для клиентов,
  которые различают одно и другое.

## 2. Ограничения среды

- Генератор целится в PHP 7.4–8.5. Union-типы — с 8.0, `new` в инициализаторах и enum — с 8.1, readonly-классы — 8.2.
- Неинициализированное типизированное свойство существует с 7.4 и уже различает «не задано»: чтение бросает `Error`,
  `ReflectionProperty::isInitialized()` отвечает.
- Symfony Serializer: денормализация — через конструктор (параметр без ключа получает свой default), остальные
  атрибуты — через PropertyAccess/рефлексию; нормализация по умолчанию **пропускает неинициализированные свойства**
  (`skip_uninitialized_values = true`, проверено на 8.1). Readonly-свойство снаружи класса записать нельзя — PropertyAccess
  упадёт, поэтому неинициализированные свойства несовместимы с immutable-DTO на 8.1+ (`readonly`).
- Symfony Validator: констрейнты пропускают `null`; объект-маркер они считают обычным значением (ошибка типа).

## 3. Варианты

### A. Оставить как есть (текущее)

Документированное ограничение. Цена — строки 3–4 таблицы. Работает везде.

### B. Маркер «нет значения» (sentinel)

Тип свойства `T|null|Absent`, default параметра — `Absent::Value` (enum, 8.1+), метод `has<Prop>(): bool`.

- **+** Честная модель, immutable/readonly сохраняются, конструктор по-прежнему единственный путь.
- **−** Только PHP 8.1+ (enum как default, union-типы). На 7.4/8.0 — нужен другой путь или ошибка конфигурации.
- **−** Каждому потребителю — `instanceof Absent`/`has*()` при чтении; геттер возвращает union.
- **−** Мост: нормалайзер, пропускающий `Absent` при записи (по аналогии с `AdditionalPropertiesNormalizer`); каждый
  констрейнт — обернуть в `When('this.hasX()')` или собственный констрейнт; PHPDoc/PHPStan-типы шире.
- **−** Где жить `Absent`: в рантайм-пакете (мост тянет генератор в prod — см. CR-014 E5) или генерировать в
  namespace каждого источника.

### C. Неинициализированные свойства (presence через состояние объекта)

Необязательное свойство без default; конструктор принимает только обязательные; необязательные задаются setter'ом или
десериализатором; `has<Prop>()` через `isset`/`ReflectionProperty::isInitialized()`.

- **+** Работает на 7.4+; Symfony нормализует «как надо» без моста (пропускает неинициализированные); JSON без ключа
  ↔ объект без значения.
- Проба (Symfony Serializer 8.1, `ObjectNormalizer` + `ReflectionExtractor`, обязательное через конструктор,
  необязательное — setter): `{"id":"a"}` → свойство не инициализировано → обратно `{"id":"a"}`;
  `{"id":"a","nickname":null}` → задано `null` → обратно с `"nickname":null`. Различие сохраняется в обе стороны.
- **−** Ломает immutable-модель: readonly-свойства (8.1+ по умолчанию) снаружи не инициализировать, `with*()` на
  клонах 8.1–8.4 невозможны. Реально применимо только к `mutability: mutable` (или к свойствам без `readonly`).
- **−** Обращение к незаданному свойству — `Error`, геттеры должны быть `?T` + проверка, иначе падение в рантайме.
- **−** Конструктор больше не задаёт все поля — расходится с DTO-дисциплиной проекта.

### D. Явное множество заданных ключей

Генерируемое поле `list<string> $present` (или bitmask), конструктор с параметром `array $present = []`,
`has<Prop>()` по нему; `with*()` добавляет ключ.

- **+** PHP 7.4+, immutable сохраняется.
- **−** Десериализатор не знает, что передать в `$present`: нужен денормалайзер в мосте (смотрит на ключи данных) или
  фабрика `fromArray()` — генератор сейчас не генерирует (де)сериализацию. Без моста модель расходится с данными.
- **−** Два источника правды (значение и `$present`), легко рассинхронизировать при ручном создании.

### E. Только строка 3 таблицы (без различия, но честные типы)

Необязательное и не nullable свойство — тип `T` с default из схемы, а без default — … нечего подставить: снова нужен
маркер или неинициализированность. Сам по себе вариант не существует; это аргумент, что строка 3 требует B, C или D.

## 4. Сравнение

| | A | B (sentinel) | C (uninitialized) | D ($present) |
|---|---|---|---|---|
| PHP 7.4–8.0 | да | нет | да | да |
| immutable / readonly | да | да | **нет** | да |
| Symfony без моста | да | нет | **да** | нет |
| Запрет `null` для строки 3 | нет | да | да | да (с валидатором моста) |
| Merge-patch | нет | да | да | да |
| Сложность генератора | — | высокая | средняя | средняя |
| Сложность моста | — | высокая | низкая | средняя |

## 5. Рекомендация

Делать **опционально** (по умолчанию — A, вывод не меняется), одним из двух путей по ответу владельца:

1. **C для mutable-DTO** — `dto.absentProperties: tracked` разрешён только при `mutability: mutable` (или
   `x-dto-mutable: true` на схеме), иначе ошибка конфигурации. Минимальная цена, работает на 7.4+ и с Symfony из
   коробки. Подходит, если PATCH-DTO — отдельные mutable-схемы.
2. **B для PHP 8.1+** — если нужен merge-patch на immutable-DTO. Дороже всего (генератор + мост: нормалайзер,
   обёртка констрейнтов), и только для целей 8.1+.

D не рекомендую: два источника правды и обязательный денормалайзер без выигрыша над B.

## 6. Вопросы владельцу

1. Нужно ли различие для **immutable**-DTO (тогда B, 8.1+), или достаточно mutable-схем PATCH (тогда C)?
2. Включать на весь проект (`dto.absentProperties`) или на схему (`x-dto-absent: tracked`)?
3. Строку 3 (необязательное не nullable) исправлять в том же режиме (запрет `null`), или отдельно?

## 7. Решение (2026-10-11 UTC)

Владелец: «если ключа нет — то либо брать из default, либо null. И всё». Остаётся вариант A: отсутствующий ключ даёт
`default` схемы или `null`, различие с явным `null` не отслеживается, режимов и расширений не добавляем. Ограничение
описано в `docs/openapi-support.md` (Known limitations).

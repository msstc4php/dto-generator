## 2. Решения

### 2.1 Union-база как интерфейс (P2)

PHP даёт один родительский класс, но сколько угодно интерфейсов. Symfony Serializer ищет `DiscriminatorMap` у
родителя, затем у интерфейсов (`ClassDiscriminatorFromClassMetadata::resolveMappingForMappedObject`).

- Дискриминированная union-схема без собственных свойств (только `oneOf`/`anyOf` и `discriminator`) становится
  **интерфейсом**, если хотя бы один её вариант уже получил другого родителя (свой `allOf`) или усыновлён другой
  union-базой. Иначе — абстрактный класс, как сейчас (обратная совместимость).
- Интерфейс пуст (маркер): общие свойства вариантов на нём не объявляются. `DiscriminatorMap` — на интерфейсе.
- Варианты `implements` интерфейс (несколько — в порядке перечисления). Конструктор варианта не проверяет значения
  дискриминатора интерфейсов (это делает тип свойства варианта: `const`/`enum`).
- Свойство с типом union-схемы получает тип интерфейса; `Valid` моста работает так же.
- Union-схема **со** своими свойствами и вариантом с чужим родителем — ошибка, как сейчас.

### 2.2 Inline-варианты (P1)

- Inline-объект в дискриминированном union генерируется как класс: имя из `title`, иначе `<Base>Option<N>`.
- Значение дискриминатора варианта — единственное значение его свойства-дискриминатора (`const` или `enum` из одного
  значения); `discriminator.mapping` на inline-вариант сослаться не может. Нет такого значения — ошибка (как сейчас).

### 2.3 Проверка членов union (мост, рантайм 1.3)

Значение non-discriminated `oneOf`/`anyOf` (скаляр, enum, mixed) с ограничениями в нескольких членах:
- `anyOf` → Symfony `AtLeastOneOf` (Symfony 5.1+), по `Sequentially`… набору ограничений каждого члена;
- `oneOf` → новый `ExactlyOneOf` рантайма 1.3 (ровно один член без нарушений).
Сейчас такие ограничения не проверяются (README моста).

### 2.4 `allOf` на union (P3)

Оставить ошибкой: два случая, смысл («один из вариантов и ещё свойства») требует пересечения классов. Описать.

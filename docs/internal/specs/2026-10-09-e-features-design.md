# Подпроект E — новые возможности ядра и моста

**Дата:** 2026-10-09 (UTC). **Статус:** утверждена владельцем 2026-10-09 (UTC): дискриминатор — вариант B, E5 отложен, имена членов `oneOf` — как в §3.1.
**Основа:** аудит ядра и моста (подпроекты A–D, решения «Отложить в E»), замечания аудита документации B.
**Релизы:** ядро `1.2.0` (новый ключ конфига и новый публичный метод — minor), мост `1.1.0` (требует ядро `^1.2`).

## 1. Цель

Закрыть пробелы, из-за которых реальные спецификации OpenAPI не генерируются или генерируются с потерей смысла, и
довести мост до паритета с CLI. Критерий успеха: каждая возможность ниже покрыта golden-тестом и тестом на целях
7.4…8.5 (`make test-targets`), мост — матрицей Symfony 5.4/6.4/7.4/8; MSI 100%; BC-check не находит нарушений.

## 2. Состав и порядок

Пять независимых этапов, у каждого свой план в `docs/internal/plans/` и свой цикл ревью.

| Этап | Репозиторий | Содержание |
|---|---|---|
| E1 | ядро | Покрытие схем: вынос инлайн-объектов из `oneOf`/`anyOf` и компонентных алиасов, `const`, смешанные `enum`, `x-enum-varnames`, предупреждения о неподдерживаемых ключевых словах |
| E2 | ядро | Форма кода: проверка значения дискриминатора в вариантах, `dto.withers` |
| E3 | ядро | Публичный API: `@api`, `DtoGenerator::prepareProcess()` |
| E4 | мост | Паритет команды бандла с CLI, форматы `int32` и `byte` |
| E5 | мост | Нормалайзер `$additionalProperties` для Symfony Serializer (по выбору пользователя) |

Порядок E1 → E2 → E3 → релиз ядра 1.2.0 → E4 → релиз моста 1.1.0. E5 отложен решением владельца (2026-10-09 UTC); §7 сохраняется как задел.

## 3. E1 — покрытие схем

### 3.1 Вынос инлайн-объектов везде

Сейчас инлайн-объект (и инлайн-enum) выносится в класс только у свойства, его `items` и `additionalProperties`. В
`oneOf`/`anyOf` и в `items`/`additionalProperties` компонентной схемы-алиаса — ошибка «move it to components/schemas»
(для enum — предупреждение и базовый тип).

Новое правило: инлайн-объект или инлайн-enum выносится в любой позиции, где он задаёт тип значения.

| Позиция | Имя класса |
|---|---|
| `items` алиаса `Pets` | `PetsItem` |
| `additionalProperties` алиаса `Tags` | `TagsValue` (суффикс — как у свойств) |
| `oneOf`/`anyOf`, член `i` (с 1), у свойства `either` класса `Holder` | `title` члена в PascalCase, иначе `HolderEitherOption<i>` |
| `oneOf`/`anyOf`, член `i`, у компонентной схемы `Shape` | `title` в PascalCase, иначе `ShapeOption<i>` |

- `x-php-class-name` на инлайн-члене переопределяет имя, как и везде.
- Коллизия — существующая ошибка с подсказкой `x-php-class-name`.
- Вложенность рекурсивна: член `oneOf` с инлайн-свойством даёт `HolderEitherOption1Address` и т. д.
- Инлайн-член с `discriminator` у родителя-`oneOf` не поддерживается (mapping требует `$ref`) — ошибка остаётся,
  сообщение уточняется.

### 3.2 `const`

| Схема | Сейчас | Станет |
|---|---|---|
| `const: 'a'` | `mixed` | `string`, `@phpstan-var 'a'` |
| `const: 5` | `mixed` | `int`, `@phpstan-var 5` |
| `const: true` | `mixed` | `bool`, `@phpstan-var true` |
| `const: 1.5` / `null` / массив | `mixed` | без изменений (`float`, `null`, `array` без уточнения) |

`default` по-прежнему берётся только из `default`. `type`, противоречащий `const`, — ошибка (как у `enum`).

### 3.3 Смешанные `enum`

`enum: [active, 2]` сейчас — ошибка. Станет: PHP-enum не создаётся, свойство получает `string|int` (8.0+; на 7.4 —
без нативного типа), PHPDoc — `'active'|2`, предупреждение «mixed enum has no PHP enum». Мост уже пишет `Choice` по
`enum` и продолжит это делать. Значения `float`/`bool` в enum остаются ошибкой.

### 3.4 `x-enum-varnames`

Имена case'ов (констант) по соглашению openapi-generator:

```yaml
code: {type: integer, enum: [1, 2], x-enum-varnames: [Active, Blocked]}
```

- Список той же длины, что `enum` без `null`; иначе ошибка.
- Имя нормализуется как сейчас (UPPER_SNAKE); недопустимое или повторяющееся после нормализации — ошибка.
- Ключ не начинается с `x-php-`, поэтому добавляется в словарь ядра (`ExtensionVocabulary::KNOWN`) и закрывается для
  алиасов, как `x-enum-descriptions`.

### 3.5 Предупреждения о неподдерживаемых ключевых словах

Сейчас эти ключевые слова молча игнорируются: `prefixItems`, `patternProperties`, `if`/`then`/`else`, `not`,
`dependentSchemas`, `dependentRequired`, `unevaluatedProperties`, `unevaluatedItems`, `contains`, `propertyNames`.
Станет: одно предупреждение на схему «keyword X is not supported and has no effect on the generated type».
`nullable: true` (OpenAPI 3.0) — предупреждение с подсказкой `type: [T, 'null']`. Тип не меняется: тихо принимать
`nullable` значило бы поддерживать два диалекта.

Ключевые слова, которые обрабатывает мост (`minContains` и т. п. — нет; `pattern`, `minLength`… — да), не
предупреждаются. Список живёт в одном месте — `Domain\Builder\UnsupportedKeywords`.

## 4. E2 — форма кода

### 4.1 Значение дискриминатора в вариантах

Сейчас `new Cat('dog', …)` проходит (ruling CR-015, отложено в E). Свойство-дискриминатор объявлено в базе, поэтому
ограничение на свойстве в варианте невозможно — проверку делает конструктор варианта.

**Рекомендуемый вариант (B): проверка в конструкторе.**

```php
final readonly class Cat extends Pet
{
    /**
     * @phpstan-param 'cat'|'kitty' $kind
     */
    public function __construct(string $kind = 'cat', public ?int $lives = null)
    {
        if ($kind !== 'cat' && $kind !== 'kitty') {
            throw new \InvalidArgumentException(sprintf('"%s" does not select Cat by "kind".', $kind));
        }

        parent::__construct($kind);
    }
}
```

- Допустимые значения для конкретного класса `C` и дискриминатора `D` (владелец — база `B`): ключи mapping `D`, чья
  цель — `C` или предок `C` ниже `B`; без mapping — имя схемы `C` (неявный mapping OpenAPI).
- Вложенные дискриминаторы (S-3): проверяется каждый дискриминатор цепочки предков, своим параметром.
- Одно допустимое значение — оно же значение по умолчанию; параметр остаётся (с default), поэтому Symfony
  Serializer, который передаёт значение из данных в конструктор, работает без изменений.
- Дискриминатор-enum (`$ref` на enum): сравнение с case'ами (`Kind::CAT`), на 7.4/8.0 — с константами.
- `withKind()` / `setKind()` у вариантов не генерируются: clone-withers (7.4, 8.0, 8.5) обошли бы проверку.
- Abstract-классы (промежуточные базы) не проверяют: их конструктор `protected`, значение проверит конкретный класс.
- Это первый генерируемый код, бросающий исключение. Используется только встроенный `\InvalidArgumentException`,
  зависимостей у вывода не появляется.

**Альтернатива (A):** убрать параметр из конструктора варианта и передавать константу в `parent::__construct`.
Короче, но ломает denormalize в Symfony (лишний ключ `kind` на readonly-свойстве, `ALLOW_EXTRA_ATTRIBUTES`) и не
выражает mapping с несколькими значениями. Не рекомендуется.

### 4.2 `dto.withers`

`dto.withers: true` (по умолчанию) | `false`. При `false` immutable DTO не получают `with*()`. Влияет только на
immutable; mutable-сеттеры не трогает. Мотив: на больших спецификациях withers — половина вывода, а многие проекты
их не используют.

## 5. E3 — публичный API

### 5.1 `@api`

Классы публичного API (список — фильтр `.roave-backward-compatibility-check.xml`) получают тег `@api` в PHPDoc.
Unit-тест проходит по `src/` и сверяет: класс помечен `@api` ⇔ он подпадает под фильтр BC-check. Так документация
(`docs/extensions-spi.md`), BC-check и код не расходятся. `@internal` на остальных не ставится: «без `@api` —
внутреннее» достаточно и не раздувает diff.

### 5.2 `DtoGenerator::prepareProcess()`

Сейчас подготовка процесса (stderr для `display_errors`, `memory_limit` 1G / `DTO_GENERATOR_MEMORY_LIMIT`, код `2`
для фатальной ошибки) спрятана в `private prepareRuntime()` и доступна только `run()`. Команда бандла поэтому
расходится с CLI (замечание 20 аудита B).

`prepareRuntime()` становится `public static function prepareProcess(OutputInterface $output): void` с тем же
поведением. Вызывать его можно только из одноразового процесса (CLI, консольная команда): он меняет настройки
процесса и регистрирует shutdown-функцию. Warmup-проверка бандла его не вызывает.

## 6. E4 — мост: паритет и форматы

- `GenerateCommand` бандла вызывает `DtoGenerator::prepareProcess($output)` перед `guard()`. README моста убирает
  оговорку о `memory_limit` и коде `255`.
- `format: int32` → `Range(min: -2147483648, max: 2147483647)`, объединённый с `minimum`/`maximum` (берётся более
  узкая граница). `int64` — без ограничения: совпадает с `int` PHP на 64-битных платформах.
- `format: byte` → `Regex('/^(?:[A-Za-z0-9+\/]{4})*(?:[A-Za-z0-9+\/]{2}==|[A-Za-z0-9+\/]{3}=)?$/')` (base64 RFC 4648).
- **Не добавляется:** `uri` → `Url` (Symfony `Url` отвергает `urn:`, `mailto:` и относительные ссылки — ложные
  ошибки на валидных данных), `time` (формат RFC 3339 `full-time` с часовым поясом не совпадает с `Time` Symfony).

## 7. E5 — `$additionalProperties` в Symfony Serializer (по выбору)

Сейчас мост ставит `Ignore` на `$additionalProperties`: Symfony Serializer записал бы его одним ключом.

- Настройка `extensionConfig.symfony.additionalProperties: ignore` (по умолчанию, как сейчас) | `spread`.
- При `spread` мост пишет на класс атрибут `#[Msstc4Symfony\DtoGeneratorBridge\Attribute\AdditionalProperties('additionalProperties')]`
  вместо `Ignore` на свойстве.
- Нормалайзер `AdditionalPropertiesNormalizer` (normalize и denormalize) находит классы по этому атрибуту
  (`ReflectionAttribute::getName()`, кэш по классу). Normalize раскладывает map по ключам верхнего уровня. Denormalize
  собирает необъявленные ключи в map. Остальное делегирует внутреннему нормалайзеру, защита от рекурсии — флаг
  контекста.
- Бандл регистрирует нормалайзер, если включён `framework.serializer`.
- **Ограничения:**
  - нормалайзер работает в приложении, а не в генераторе, поэтому мост нужен в `require`, а не в `require-dev`;
  - сигнатуры нормалайзеров Symfony 7+ требуют union-типов PHP 8, поэтому код лежит в `src/Runtime/`, работает с
    Symfony 6.4+ на PHP 8.1+ и исключён из PHP 7.4-профиля (deptrac, `phpstan-php74.neon`, lint);
  - на Symfony 5.4 режим `spread` — ошибка конфигурации моста.
- Это самый объёмный этап с новым runtime-кодом. Его можно отложить отдельным решением, остальные этапы от него не
  зависят.

## 8. Вне рамок

- **`readOnly`/`writeOnly`:** честная поддержка требует разных моделей для запроса и ответа. Остаётся в известных
  ограничениях; E1 их не предупреждает (это валидная аннотация, а не неподдерживаемая валидация).
- **Различие «нет ключа / `null`»** — без изменений (spec §5.2).
- **Удалённые `$ref`.**
- **`uri` и `time` в мосту** — см. §6.

## 9. Совместимость и миграция

- Все изменения вывода — только там, где раньше была ошибка или `mixed`. Исключение — E2.
  - Новая проверка дискриминатора меняет вывод существующих вариантов: значение по умолчанию, проверка, нет
    `withKind()`. Это изменение API сгенерированного кода — CHANGELOG, раздел «Changed», с примером.
  - Явного отключения нет: принимать чужое значение дискриминатора — ошибка, а не стиль.
- `x-enum-varnames` меняет имена case'ов только там, где ключ задан.
- `int32` добавляет `Range` в существующие DTO моста — CHANGELOG моста, «Changed».

## 10. Тестирование

- Каждый пункт E1/E2 — golden-фикстура в `tests/Fixtures/Projects/` на целях 7.4, 8.0, 8.1, 8.2, 8.5 и runtime-smoke в
  `tests/Targets/smoke.php`. Проверка дискриминатора: успешный вызов, исключение, значение по умолчанию.
- Мост: интеграционный тест denormalize/validate варианта с дискриминатором на всей матрице Symfony. Это проверяет
  выбор (B) против реального Serializer. Тесты `int32`/`byte` — unit и интеграция Validator.
- E5: интеграционный round-trip normalize/denormalize на Symfony 6.4/7.4/8; на 5.4 — тест ошибки конфигурации.
- Документация (`docs/*.md`, README моста, CHANGELOG) обновляется в том же этапе, что и поведение.

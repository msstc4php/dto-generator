# F3 — удалённые `$ref`: заголовки, прокси, обновление кэша

**Дата:** 2026-10-12 (UTC). **Статус:** решение принято автономно; владелец выбрал направление 2026-10-12 («давай без
Packagist»; следующий пункт списка — авторизация и прокси для удалённых `$ref`). Расширяет F2
(`2026-10-10-f2-remote-refs-design.md`), снимая три пункта его «Вне рамок».

## 1. Проблема

- Схемы во внутреннем GitLab/GitHub/Artifactory отдаются только с токеном: F2 не умеет посылать заголовки.
- В корпоративных сетях наружу ходят через HTTP-прокси: F2 соединяется напрямую и не читает `HTTPS_PROXY`.
- Обновить закэшированный документ можно только удалив его запись из `index.json` руками.

## 2. Заголовки

```yaml
remoteRefs:
  allow: [https://git.example.com/api/v4/projects/12/repository/files/]
  headers:
    - prefix: https://git.example.com/api/
      name: PRIVATE-TOKEN
      value: ${GITLAB_TOKEN}          # или 'Bearer ${SCHEMAS_TOKEN}'
```

- `prefix` — абсолютный **https**-URL без query и fragment (нормализуется, как `allow`). `http` — ошибка конфига:
  учётные данные не идут открытым текстом. Заголовок уходит только в запросы к URL под префиксом; редиректов нет
  (F2), поэтому на другой хост он не утечёт.
- `name` — токен RFC 9110. Запрещены те, что пишет клиент или прокси: `Host`, `Connection`, `Content-Length`,
  `Transfer-Encoding`, `Proxy-*`. `Accept` и `User-Agent` заменяют значения клиента.
- `value` — шаблон: `${NAME}` (`[A-Za-z_][A-Za-z0-9_]*`) подставляет переменную окружения; другой `$` — литерал,
  незакрытый `${` — ошибка конфига. Секреты в конфиг (он коммитится) не пишутся — документация говорит это прямо.
- Несколько правил на один URL: для каждого имени (без учёта регистра) побеждает самый длинный префикс. Два правила
  с одинаковыми именем и префиксом — ошибка конфига; префикс, не пересекающийся ни с одним `allow`, — предупреждение.
- Переменные ищутся в `$_SERVER`, `$_ENV`, затем `getenv()` (Symfony Dotenv по умолчанию не вызывает `putenv`).
  Имена `HTTP_*` запрещены: под CGI/FPM их задаёт клиент запроса заголовками (httpoxy).
- Переменные читаются только при скачивании: `--check` и чтение из кэша их не требуют. Не задана или пуста — ошибка
  документа «… needs the environment variable GITLAB_TOKEN for its PRIVATE-TOKEN header, which is not set.».
  Значение с управляющими символами (кроме табуляции) — ошибка. Значения заголовков не попадают ни в диагностику, ни
  в кэш.

## 3. Прокси

- Из окружения, как у curl (кроме `all_proxy`): для `https` — `https_proxy`, затем `HTTPS_PROXY`; для `http` — только `http_proxy`
  (верхний регистр в CGI задаёт клиент — httpoxy). `no_proxy`/`NO_PROXY`: список через запятую или пробел; `*` —
  без прокси; запись совпадает с хостом или его суффиксом по границе точки (ведущая точка не важна), `host:port` — только
  этот порт; IP — точное совпадение. CIDR не поддерживается.
- Адрес прокси: `http://[user[:password]@]host[:port]`, без схемы — `http://`, порт по умолчанию 1080 (curl). Другая
  схема (`https://`, `socks5://`) или мусор — ошибка документа при скачивании, с именем переменной и без учётных
  данных.
- `https` — туннель: `CONNECT host:port HTTP/1.1` (+ `Proxy-Authorization: Basic …` из userinfo, процент-декодированного),
  ответ 2xx, затем TLS с проверкой сертификата и SNI **целевого** хоста. 407 — «the proxy … requires authentication»,
  иное — «the proxy … answered N». Заголовки ответа прокси — с теми же ограничениями, что у сервера.
- `http` — `GET http://host[:port]/path HTTP/1.0` прокси, с `Proxy-Authorization`.
- Срок `timeout` охватывает и прокси. Сообщения называют прокси как `host:port`.
- Поведение меняется для тех, у кого переменные уже заданы: раньше генератор их игнорировал (CHANGELOG, «Changed»).

## 4. Обновление кэша

- `generate --refresh-remote` — скачивает заново каждый удалённый документ, который читает запуск, и заменяет запись
  индекса; прежний файл удаляется, если на него больше не ссылается ни одна запись. Только в запуске, который пишет:
  с `--check`/`--dry-run` — ошибка использования.
- API: `Generate\Input::withRefreshedRemote()` (`@api`), `refreshesRemote()` = запрошено и запуск скачивает.
- Документ в одном запуске скачивается один раз: загрузчик схем помнит удалённые документы своего запуска (`Reads`).
  Повторный запуск того же генератора читает и обновляет их заново.
- Файл документа пишется под той же блокировкой, что и индекс: обновление не удалит файл, который параллельный
  запуск вот-вот внесёт в индекс. Сообщения о битой копии предлагают `--refresh-remote`.

## 5. Архитектура

- Application: `Config\RemoteHeader` (префикс, имя, шаблон; `variables()`, `render(array<string, string>)`, грамматика
  полей — `Application\Port\HttpField`), `RemoteRefsSettings::headersFor(url)`; порт `Port\RemoteDocuments::load(string
  $url, RemoteRequest $request)`, `Port\RemoteRequest` (каталог кэша, срок, `RemotePolicy` `cached|missing|all`,
  заголовки). Порт внутренний — BC не затрагивает.
- Infrastructure: `CachedRemoteDocuments` подставляет переменные (через `Remote\Environment`: `$_SERVER` → `$_ENV` →
  `getenv`) и передаёт заголовки `Fetcher::get()`; `Remote\Proxies` (из окружения) и `Remote\Proxy`,
  `Remote\Environment`; `StreamFetcher` строит запрос и туннель, `Remote\Connection` держит сокет под общим сроком (TCP,
  TLS, чтение заголовков и тела). Для тестов `StreamFetcher` принимает файл доверенных сертификатов (`@internal`).

## 6. Вне рамок

- Прокси из конфига, SOCKS, HTTPS-прокси (TLS до прокси), CIDR в `no_proxy`.
- Basic-авторизация к серверу отдельным ключом (значение `Basic …` собирается в переменной окружения).
- `--refresh-remote` у команды моста; удаление записей кэша, которые больше никто не читает.

## 7. Тестирование

- Юнит: разбор `headers` (все ошибки), выбор заголовков по префиксу, шаблоны, `Proxies` (переменные, `no_proxy`,
  порты, IPv6, мусор), `CachedRemoteDocuments` (заголовки, неустановленная переменная, управляющие символы, обновление
  и удаление прежнего файла), CLI (`--refresh-remote`, конфликт с `--check`).
- Интеграция: тестовый прокси на 127.0.0.1 — `CONNECT` к TLS-серверу (`openssl s_server`, самоподписанный сертификат
  как доверенный), `http` через прокси, `Proxy-Authorization`, 407; заголовки доходят до сервера.
- Infection: MSI 100 %.

## 2. Классы ошибок

- **A. Имена из одних знаков.** `+1` и `-1` (реакции GitHub) оба становятся `$_1` и case `_1`; `*` не даёт имени
  вовсе. Решение: ведущие `+`/`-` перед цифрой и одиночные знаки пишутся словами (`plus1`, `minus1`, `asterisk`) —
  только там, где сегодня ошибка, чтобы не менять уже сгенерированные имена.
- **B. Конфликт имён классов.** Имя inline-схемы (выведенное из пути или из `title`) совпадает с компонентом или с
  другой inline-схемой. Решение: inline-схема уступает: следующее по порядку выведенное имя, затем числовой суффикс.
- **C. Разные типы одного свойства в ветвях `allOf`.** По JSON Schema применяются обе ветви, то есть тип —
  пересечение. Решение: `TypeMeet` берёт более узкий тип, когда один допускает все значения другого (`mixed`,
  `string` ⊇ формат/enum, `float` ⊇ `int`, `T|null` ⊇ `T`, списки и карты поэлементно, `array<mixed>` ⊇ класс,
  объединения по членам); несовместимые остаются ошибкой.
- **D. Потомок повторно объявляет свойство родителя.** Решение: тот же тип (или шире) — свойство остаётся у
  родителя, предупреждение; уже — ошибка, как сейчас (PHP не сужает тип свойства в потомке).
- **E–G (OpenAI): unions.** Вариант, у которого уже есть родитель; вариант не `$ref` на объект; inline-объект в
  дискриминированном union; `allOf` на union — относятся к пункту 2 (`oneOf`/`anyOf`).

## 3. Итог (2026-10-14 UTC)

A–D сделаны (ветка ядра `feat/corpus-fixes`). GitHub: 5842 класса, все грузятся, метаданные Validator и Serializer
читаются; время 99 с с мостом против 43 с без него (профиль Stripe размазан, явного узкого места нет — кандидат на
отдельную оптимизацию). Дополнительно найдено и сделано: inline-объекты одного свойства (и его `items`/вариантов) в
нескольких ветвях `allOf` — один класс (`Registry::join`, `Composition::withCompanions`), иначе `TypeMeet` не
сводил два разных класса. Повторное объявление в потомке — свойство остаётся у родителя (мост пока не проверяет
сужение потомка — пробел, записан). OpenAI остаётся на пункт 2 (E–G).

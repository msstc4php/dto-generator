# F4 — режим моделей чтения и записи для отдельной схемы (`x-php-read-write`)

**Дата:** 2026-10-12 (UTC). **Статус:** решение принято автономно; владелец выбрал направление 2026-10-12 («давай
дальше по списку»: п. 4 — настройка `readWriteModels` на схему). Расширяет F1
(`2026-10-10-f1-read-write-models-design.md`), снимая первый пункт его «Вне рамок».

## 1. Проблема

`dto.readWriteModels` действует на весь запуск. Чтобы разделить на представления одну-две схемы (например, `User` с
`password: writeOnly`), приходится включать `split` для всех и получать `…Read`/`…Write` у каждой схемы с флагами — или
наоборот, нельзя исключить из `split` схему, чьи флаги не важны.

## 2. Решение

Ключ схемы класса `x-php-read-write: single | split` переопределяет `dto.readWriteModels` для этого класса — как
`x-dto-mutable` переопределяет `dto.mutability`:

- действует на схему, которая становится классом, — именованную или инлайн-объект; инлайн-объекты его **не
  наследуют** от владельца (как `x-dto-mutable`); на enum, псевдониме и члене `allOf` — «has no effect here»;
- значение не `single`/`split` — ошибка «"x-php-read-write" must be "single" or "split".», класс строится по
  `dto.readWriteModels`;
- режим класса = ключ его схемы, иначе `dto.readWriteModels`.

## 3. Семантика

- **Собственная направленность** (F1 §4 п. 1) учитывается только у класса в режиме `split`: в режиме `single`
  `readOnly`/`writeOnly` его свойств игнорируются — их флаги не читаются и не сообщаются, свойства остаются в обоих
  представлениях.
- **Распространение** (F1 §4 пп. 2–4: ссылки, наследование, варианты) — прежнее, независимо от режима: класс, который
  держит, расширяет или перечисляет класс с представлениями, тоже получает представления, иначе его тип указывал бы на
  несуществующий класс. Если у такого класса стоит явный `x-php-read-write: single` — warning «"x-php-read-write:
  single" is overridden: the class holds, extends or lists a class with read and write views, so it gets them too.»
  на ключе.
- Фильтр свойств и выноса инлайн-классов (F1 §5) применяется только к классам в режиме `split`.
- Без единого класса в режиме `split` с направленным свойством результат — сборка `single`, байт в байт как раньше.

## 4. Конфиг

`readWriteSuffixes` теперь действует и при `readWriteModels: single` (для схем с `split`), поэтому предупреждение
«"readWriteSuffixes" has no effect without "readWriteModels: split".» убирается.

## 5. Архитектура

- `Domain\Builder\ReadWriteMode`: `declared(Schema): ?ReadWriteModels` (ключ, `null` без ключа или при неверном
  значении), `check(Schema, Diagnostics)` (ошибка значения).
- `PropertyView` получает режим по умолчанию и `appliesTo(Schema $class)`; `ClassBuilder` и `Registry::excluded()` /
  `admits()` фильтруют свойства только у класса, к которому вид применим. `ClassBuilder::build()` проверяет значение
  ключа (в каждой сборке; дубликаты сборок отбрасывает `Views::merge`).
- `Build\Action` идёт через `Views` всегда; `Views` получает режим по умолчанию: семена — только классы в режиме
  `split`, предупреждение о переопределённом `single` — после замыкания.
- `ExtensionVocabulary`: ключ в `KNOWN`, `CLASS_SCHEMA` и `CLASS_DECLARATION` (инлайн-объекты; не в общем
  `DECLARATION`, который берут и enum-ы).
- При `allOf` с `merge` класс следует своему режиму, а не режиму схем, которые он копирует: флаги скопированных
  свойств учитываются, только если сам класс в режиме `split`.

## 6. Совместимость

Без ключа вывод не меняется ни в `single`, ни в `split`. Пропало одно предупреждение конфига (§4). CHANGELOG — «Added».

## 7. Вне рамок

- Наследование ключа инлайн-объектами и потомками `allOf`.
- Режим «только чтение» / «только запись» (одно представление).

## 8. Тестирование

- Юнит (`BuildViewsTest`): `split` на схеме при глобальном `single` (представления, распространение на держателя,
  прочие схемы с флагами — одна модель, их флаги не сообщаются); `single` на схеме при глобальном `split` (одна
  модель, флаги игнорируются, в т. ч. «оба флага» не сообщается); явный `single`, переопределённый распространением
  (warning, свойства обоих направлений в обоих представлениях); инлайн-объект не наследует; неверное значение —
  ошибка, один раз; ключ на enum — «no effect».
- `ConfigFactoryTest`: суффиксы без `split` — без предупреждения.
- Golden: без изменений. Infection: MSI 100 %.

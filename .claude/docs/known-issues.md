# Известные особенности

- **Числовые ключи PHP-массивов.** Имена свойств (`"200"`) и значения discriminator (`"1"`) PHP хранит как `int`-ключи. Внутри — `array<int|string, …>`, наружу — только через `propertyNames()` / `values()`, которые приводят к строке. Поиск по строке работает (PHP приводит ключ сам).
- **`AbstractEnum` и сериализация.** Экземпляры интернированы; `unserialize` создал бы второй экземпляр и сломал `===`, поэтому `__sleep`/`__wakeup` бросают `LogicException`.
- **Зарезервированные сегменты namespace** (`App\Dto\Public`) модель пропускает — на PHP 7.4 это parse error. FQCN приходят не только из `sources[].namespace`, но и из `x-php-type`, `formats.*.type`, `x-php-attributes`, `attributeAliases.*.class` и от SPI-enricher'ов. **Требование к этапу 3:** emitter для target < 8.0 проверяет каждый выводимый `ClassName` через `reservedNamespaceSegments()` и выдаёт диагностику; этап 2 — то же для конфига.
- **Сырые JSON-типы проверяет загрузчик/Builder, не модель.** `Schema::$additionalProperties` (`bool|Schema|null`) и `EnumCase::$value` (`int|string`) типизированы только PHPDoc; рантайм-guard'ы убраны — при PHPStan max их нельзя протестировать. Этапы 2/4 обязаны выдавать диагностику с `SchemaLocation` до создания модели. Для enum'ов отклонять явно и `bool` (`is_int(true)` — false, `true` проскочил бы в string-enum), и `float`.
- **Требования к следующим этапам из финального ревью этапа 1:**
  - `UnionType` дедуплицирует по ключу идентичности: имена классов — без учёта ASCII-регистра (`Foo\Bar|foo\bar` — дубль), PHPDoc-литералы и константы — как есть (`'Active'|'active'` — два члена). Но `int` и `positive-int`, `list<int>` и `array<array-key, int>` остаются разными, а нативно это `int|int` / `array|array` — compile error. Emitter (этап 3) обязан дедуплицировать нативные типы. Ключ идентичности строится по `describe()`, поэтому разные виды с одинаковым текстом (`ScalarType::string('list<Foo>')` и `ListType(Foo)`) сольются — при появлении PHPDoc-уточнений со структурой (этап 4) перейти на структурный ключ с префиксом вида.
  - `MapType` описывается как `array<array-key, T>` (spec §5.1, решение владельца 2026-10-01 UTC): PHP хранит числовые ключи JSON-объекта как `int`, генерируемый код ключи не приводит.
  - `DocModel` хранит текст как есть (только `trim`): экранирование `*/` в docblock — обязанность emitter'а (spec §5.5). `trim` срезает и ведущий отступ первой строки — если в description бывает markdown-код, emitter должен брать сырой текст из `Schema`.
  - `ClassModel` не проверяет, что `discriminator->propertyName()` есть среди wire-имён: свойство может быть унаследовано — проверка в Builder'е (этап 4).
  - `AttributeModel` пока без цели (класс / свойство / параметр конструктора, spec §8) — добавить в этапе 5 со значением по умолчанию.
  - Catch-all `$additionalProperties` (spec §5.1) не имеет wire-имени, а `PropertyModel` требует непустое уникальное — до этапа 4 нужен флаг или отдельная модель, иначе коллизия с настоящим свойством `additionalProperties` и неверный `SerializedName`.
  - `INF`/`NAN` из YAML (`.inf`, `.nan`) доходят до `DefaultValue` и `Schema::enum`, а `ArgumentValue` их отклоняет — Builder/Emitter должны выбрать одну политику (отказ или `\INF`).
  - `ClassType` не знает, ссылается ли на enum (важно для 7.4/8.0: `string` + PHPDoc `Name::*`) — emitter решает через реестр моделей.
- **Различие «нет ключа / null»** в v1 не моделируется (spec §5.2).
- **Rector и `@return static`.** `RemoveDuplicatedReturnSelfDocblockRector` удаляет `@return static` у фабрик `AbstractEnum` (типизация наследников ломается) — правило в `withSkip`. `make fix` запускает Rector **до** CS-Fixer: Rector оставляет FQCN, CS-Fixer их сокращает.
- **Строгость PHPUnit на 7.4.** Образ `php:7.4-cli` без php.ini, его `error_reporting` = 22519 (без notice/deprecation) — поэтому в `phpunit.xml.dist` `error_reporting=-1`.
- **Первый сегмент `namespace`** (`Namespace\Dto\User`) отклоняется для любых целей: лексер читает `namespace\X` как namespace-relative имя.
- **`ImportAlias` намеренно не через `ClassName`:** последний сегмент namespace не короткое имя класса, зарезервированные слова там допустимы.
- **Docker-цели в песочнице Claude Code.** `make check` (`lint-74`), `make test-74` обращаются к `docker.sock` — внутри песочницы падают с `permission denied`; запускать вне песочницы.
- **PHPStan и JSON.** Алиасы типов PHPStan не бывают рекурсивными, поэтому `JsonValue` = `JsonScalar|array<array-key, mixed>`.
- **YAML без кавычек.** `default: 2020-01-01` → int-timestamp (`symfony/yaml` без `PARSE_DATETIME`); `php: 8.2` → float (конфиг это обрабатывает). В спецификациях даты и версии нужно кавычить — Builder (этап 2b) должен предупреждать о int-default у `format: date/date-time`.
- **Объект с ключами `"0"`, `"1"`…** (например, `properties` с такими именами) неотличим от списка после декодирования и сообщается как «must be an object».
- **Пути лексические.** Symlink'и не раскрываются: один файл под двумя разными путями даст две схемы. `..` и `.` нормализуются.
- **Удалённые `$ref` и якоря** (`$anchor`, `#Name`) не поддерживаются — ошибка с подсказкой.
- **`target.php: auto`** берёт нижнюю границу `require.php` ближайшего `composer.json` (только PHP; версии пакетов — этап 6 / мост). Вне диапазона 7.4–8.5 — предупреждение и ближайшая поддерживаемая версия.
- **Ссылочные схемы с `selected=false`** всё равно должны генерироваться (иначе тип свойства повиснет) — этап 2b решает именование и namespace по `source`.
- **`composer.json` без прав на чтение** даёт `null` (не PHP-warning): `is_readable()` проверяется до `file_get_contents()`.
- **Песочница Claude Code и права файлов.** Внутри bubblewrap процесс выглядит как root, поэтому тесты с `chmod 0000` пропускаются (`markTestSkipped`); `make infection` и `make verify` запускать вне песочницы.
- **Числовые ключи в конфиге** (`formats: {"200": …}`) — тоже `int|string`; типы в `GeneratorConfig` это отражают.
- **YAML-числа.** symfony/yaml 5.4 читает `010` как восьмеричное (8), ключ `0123:` → 83; большое целое в YAML остаётся строкой, в JSON становится float. `openapi: 3.1` без кавычек — float (обрабатывается), но `php: 8.10`/`openapi: 3.10` неотличимы от `8.1`/`3.1` — версии нужно кавычить. Builder (этап 2b) должен предупреждать о подозрительных `enum`/`default`.
- **Регистр путей.** На регистронезависимых ФС `A.yaml` и `a.yaml` — один файл, но два ключа (две схемы). Буква диска (`c:` → `C:`, и в `c:foo`) нормализуется; `//server/share` (сервер **и** share) — корень UNC, а `//x` — обычный POSIX-путь `/x`; корень UNC, выше него `..` не поднимается, `Path::directory()` на нём останавливается.
- **Голое имя в `discriminator.mapping`** разрешается относительно файла с discriminator, а не корневого документа OpenAPI (по спецификации — корневого). Имена с `.json/.yaml/.yml` считаются путями.
- **Незагружаемый файл сообщается один раз** — в месте первого обращения (источник или `$ref`); остальные ссылки в него молча пропускаются.
- **`TargetResolver` предупреждает**, если ближайший `composer.json` нечитаем, невалиден или `require.php` не строка, и берёт PHP 7.4.

- **Акронимы в именах свойств.** `URL_PATH` → `urlPATH`: в нижний регистр приводится только первое слово (целиком в капсе или ведущий акроним `HTTPStatus` → `httpStatus`); акронимы внутри (`xmlHTTPRequest`) не трогаются. Нужен другой вид — `x-php-name`.
- **Infection-эквиваленты в `DefaultFit::inRange`:** `CastInt` и `PregMatchRemoveCaret` проигнорированы — уточнения строит только `TypeMapper`.
- **Required + default.** Default обязательного не-nullable свойства игнорируется молча (spec §5.2: обязательный аргумент без значения).
- **Схема без типа** (`{}`) → `mixed`; `type: object` без `properties` → `array<array-key, mixed>`.
- **Формат вывода.** `GeneratedCodePrinter`: списки параметров/аргументов длиннее 80 байт (длина самого списка, не строки) или с многострочным элементом/PHPDoc — по одному на строку, многострочная сигнатура закрывается `) {` (сборка сигнатуры структурная, без регэкспа по тексту); висячая запятая в разбитых аргументах и массивах — на всех целях (7.3+); висячая запятая в параметрах — с 8.0 (`phpVersion` printer = цель). `use` не строятся до этапа 5 — классы вне namespace пишутся `\FQCN`.
- **Strict-режим §6.1 и union/`mixed` на 7.4.** Это не деградация: spec §5.3 прямо задаёт форму 7.4 (свойство без нативного типа + PHPDoc), поэтому ни ошибки, ни warning нет. `TargetProfile::isStrict()` понадобится для настоящих capability-пробелов (`{new: …}` на 8.0, этап 5) — диагностику выдаёт Builder/Enricher, у порта `CodeEmitter` канала диагностики нет.
- **Порядок свойств объекта.** И объявленные (7.4), и promoted свойства идут в порядке конструктора: обязательные, затем необязательные — одинаковый `get_object_vars`/JSON на всех целях.
- **Строковые default с управляющими символами** печатаются в двойных кавычках с escape (`"x\n"`), а не сырым многострочным литералом.
- **Строки описания с `@`** экранируются как `\@`, иначе PHPDoc читал бы их как теги (`@var`, `@deprecated`).
- **`x-php-name` суперглобалов** (`GLOBALS`, `_GET`, …) — ошибка Builder и инвариант `PropertyModel`: такой параметр не компилируется.
- **Свойство `clone`** при wither через `clone` (7.4/8.0): временная переменная — `$copy`. Golden-класс `Copy` (без namespace) прогоняется на целях.
- **Инварианты IR для emitter:** `PropertyModel` required ⇔ нет default; `ClassForm` строится только `mutable()`/`immutable()`; не-final класс со свойствами emitter отвергает до этапа 4 (`new self` в abstract недопустим).
- **symfony/console 5.4 и PHPStan (phpVersion 70400):** phpdoc `mixed` у `getOption()`/`addOption()` PHPStan читает как класс `…\mixed`; stub-файл не применился. Опции читаются через `getOptions()` (там phpdoc типизирован).
- **Writer:** `plan()` получает список ВСЕХ outputDir конфига — иначе источник, у которого удалили все схемы, не почистит устаревшие файлы. Файл без `@generated` не перезаписывается даже если он в манифесте (заголовок стёрт руками) — ошибка.
- **Генерация файлов** пропускается, если схемы/модель дали ошибки (`files()` → null): записи всё равно не будет.
- **Пути файлов:** Build кладёт каждый класс прямо в namespace источника → файл `<outputDir>/<ShortName>.php`; вложенные namespace появятся только с этапом 4+.
- **CI (`.github/workflows/ci.yml`) локально не прогонялся**: матрица PHP 7.4–8.5 × lowest/highest (`composer config platform --unset`), static на 8.4, `make test-targets`, infection.
- **Writer после ревью 3b:** коллизия файлов в одном outputDir (без учёта регистра) — конфликт; ключи манифеста проверяются `GeneratedFile::isSafeRelativePath` (нет `..`, `/` в начале, `\`, `:`, NUL) — иначе манифест «битый» и это ошибка (как и невалидный JSON); перед записью файлов пишется промежуточный манифест (новые + ещё не удалённые), после — итоговый; temp-файл удаляется при сбое; NUL в outputDir отвергается ещё в `plan()` (PHP 7.4 бросает `TypeError` на `file_exists`); удаления выполняются до записей (переименование Foo→FOO на регистронезависимой ФС); CRLF нормализуется и для манифеста; права: обновляемый файл сохраняет свои, новый — `0666 & ~umask()`, `chmod` не фатален; нечитаемый файл — конфликт; CRLF-копия = unchanged; права обновляемого файла сохраняются; блокировки — `DirectoryLocks`: `flock` на `sys_get_temp_dir()/dto-generator-<sha1(realpath)>.lock`, общий реестр процесса со счётчиком (два writer'а одного процесса не ждут друг друга), захват в отсортированном порядке, best effort (нет прав на lock-файл — без блокировки); держится от `plan()` до `apply()`/`release()` — `Generate` вызывает `release()` в `finally`.
- **CLI:** `bin/dto-generator` → `DtoGenerator::run()`: ошибки ввода symfony (`ExceptionInterface`) → 3, прочие `Throwable` → 2 (иначе symfony отдаёт 1, что значит «устарело»). Команда регистрируется через `FactoryCommandLoader` (в symfony 7.4 `add()` deprecated). Диагностика в stderr (text), отчёт в stdout; при `--format=json` и ошибки использования — JSON.
- **Lock-файлы** `dto-generator-<sha1>.lock` остаются в системном временном каталоге (по одному на outputDir) — не удаляются намеренно: unlink у flock-файла создаёт гонку. Ключ — realpath ближайшего существующего предка + хвост (symlink и ещё не созданный каталог дают тот же ключ). Ожидание блокировки — без таймаута и без сообщения: у writer нет канала вывода (решение ревью 3b, CR-012).
- **JSON-вывод** печатается с `OutputInterface::OUTPUT_RAW` (форматтер Symfony вырезал бы `<tag>` и `\<` из сообщений) и с `JSON_INVALID_UTF8_SUBSTITUTE` (отчёт никогда не пустой). Пути файлов обязаны быть валидным UTF-8 (`isSafeRelativePath`), поэтому манифест кодируется без подстановок и остаётся точным. Формат — `Presentation/Cli/JsonReport` (`@phpstan-type ReportShape`).
- **Interim-манифест** пишется только если в каталоге есть создания или удаления; чистые обновления пишут манифест один раз.

# Доменная модель

## Schema (`Domain/Schema`)
- `Schema` — неизменяемый узел; собирается через `SchemaBuilder`. Ключевые слова со своими accessor'ами (`Schema::STRUCTURAL_KEYWORDS`) и `x-*` нельзя класть в `keywords` — один источник истины.
- `SchemaLocation` — файл + JSON pointer (RFC 6901, `~`→`~0`, `/`→`~1`); используется в каждой диагностике.
- `Extensions` — только ключи `x-<name>`; порядок — как в документе.
- `default` обёрнут в `DefaultValue`: «default = null» ≠ «default нет».

## IR (`Domain/Model`)
- `TypeModel`: `ScalarType` (с PHPDoc-уточнением), `ClassType`, `ListType`, `MapType` (`array<array-key, T>` — числовые ключи JSON становятся int), `UnionType` (≥2 разных, плоский, без nullable/mixed), `NullableType` (не вкладывается, не над mixed), `MixedType`. Равенство типов — по `describe()`.
- `ClassName` отклоняет зарезервированные слова (включая soft keywords `enum`, `readonly`) только в **коротком имени**; сегменты namespace — лишь синтаксис идентификатора, т.к. с PHP 8.0 `App\Dto\Public` допустим. Отказ для target < 8.0 — обязанность валидации конфига (этап 2). Переименование (суффикс `_`) делает Builder, не модель.
- `Identifier`: проверка с `\z`; два списка — `PHP74_KEYWORDS` (токены лексера 7.4: ломают и имя класса, и сегмент namespace до 8.0) и `RESERVED_CLASS_NAMES` (`enum`, `match`, `readonly`, имена типов — только для имени класса); `resource`/`numeric` разрешены (soft-reserved, компилируются везде); `normalizeQualifiedName()` — общая проверка FQCN/namespace (ровно один ведущий `\`); `asciiLower()` — локаленезависимый lower.
- `ClassName::equals()` регистронезависим (как PHP); `reservedNamespaceSegments()` — для проверки target < 8.0. Список зарезервированных включает `die`, `__halt_compiler`, магические константы.
- `PropertyModel`: запрещено только точное `this` (`$This` — законная переменная). `wireName` — исходное имя из схемы (для `SerializedName` в мосте).
- `ClassModel`: уникальны PHP-имена (регистронезависимо — иначе столкнутся `getFoo()`) и wire-имена; discriminator только у `ClassKind::ABSTRACT`; `with*()` пересоздают объект и заново проверяют инварианты.
- `EnumModel`: значения строго типа backing'а (`'1'` в int-enum — ошибка), без дублей имён и значений; case `class` запрещён.
- `AttributeModel` + `ArgumentValue` (literal / list / map / constant / class-reference / new-instance) — общий вход для рендереров атрибутов и аннотаций. Порядок аргументов: позиционные, затем именованные без повторов. `INF`/`NAN` запрещены.

## Target (`Domain/Target`)
- `Capability` — матрица «возможность → минимальная версия PHP» (spec §6.1). Новая версия PHP = строка в `PhpVersion::SUPPORTED` + строки в матрице.
- `TargetProfile` валидирует сразу: `metadata=attributes` требует 8.0; `public-properties` для immutable требует readonly (8.1). `configuredAccessors()` может вернуть `AUTO` — генерация обязана использовать `accessorsFor()`, который разрешает `auto` по мутабельности конкретного класса (её можно переопределить `x-dto-mutable`).

## Диагностика и граф (этап 2a)
- `Diagnostics` — изменяемый сборщик (collecting parameter); `Diagnostic` = severity + сообщение + `SchemaLocation|null`. Ошибки конфига адресуются тем же `SchemaLocation` (файл конфига + JSON pointer).
- `SchemaParser` всегда возвращает `Schema`; неверный keyword → диагностика и пропуск.
- `SchemaGraph::resolve(ReferenceUse)` — по рёбрам, записанным при загрузке (не бросает); `Reference::target()` — `$ref` → `SchemaLocation` (лексически, без ФС); `null` для `scheme://`; якоря (`#Name`) не поддерживаются; фрагмент и путь проходят `rawurldecode`.
- `Discriminator` хранит mapping нормализованным: голое имя → `#/components/schemas/<имя>`.
- `SchemaGraph` — ключ `file#pointer`; `ResolvedSchema.source` — индекс источника-владельца; файл вне всех источников наследует владельца от ссылающихся, двое и более → ошибка неоднозначного namespace. `selected=false` — схема нужна только как цель ссылки (генерировать её всё равно придётся, иначе ссылка повиснет — решение этапа 2b).
- `Capability::RESERVED_NAMESPACE_SEGMENTS` (8.0): ниже — `TargetResolver` отклоняет токены PHP 7.4 в namespace источников и типах `formats`.

## Builder (этап 2b)
- Класс = схема без `$ref`/`x-php-type`/неподдержанных keyword'ов, с `properties` и типом `object` или без типа (`SchemaShape::isClass`). Прочие именованные схемы — алиасы: `$ref` на них встраивает их тип (с защитой от циклов).
- Схемы только-по-`$ref` (selected=false) тоже становятся классами — в namespace источника-владельца (решение владельца 2026-10-01 UTC).
- Свойство: обязательное и не-nullable → без default; иначе `?T` и default из схемы или `null`. Default у класса (дата, `x-php-type`) или map, в том числе как элемента непустого списка, → warning и `null` (`{}` и `[]` из JSON неразличимы: пустой default у map/класса — тоже warning; у списка — сохраняется; не-список у списка — ошибка несовпадения); `INF`/`NAN` → ошибка; default, не подходящий под тип с учётом уточнений (`non-empty-string`, `positive-int`, `int<a, b>`, элементы `list`), → ошибка и `null` (`DefaultFit`).
- Имена: класс — PascalCase, ведущая цифра `_`, зарезервированное слово `_` в конце; свойство — camelCase, первое слово целиком в капсе приводится к нижнему регистру целиком, ведущий акроним тоже, с цифрами (`HTTPStatus` → `httpStatus`, `HTTP2Status` → `http2Status`, `IDs` → `ids`), `this` → `this_`. Слова делятся по не-`\p{L}\p{M}\p{N}` (combining marks NFD-имён сохраняются) (NBSP, `€` — разделители); невалидный UTF-8 — только ASCII-буквы и цифры. Коллизии — без учёта ASCII-регистра.
- `x-php-skip` действует и на алиасы (ссылка → warning и `mixed`); required + skip → warning.
- Словарь `x-php-*`/`x-dto-*` (`ExtensionVocabulary`) проверяется у каждой схемы графа: класс/enum/композиция — набор класса, алиас — `x-php-type`, `x-php-skip`; свойства — в `ClassBuilder`; любая вложенная `items`/`additionalProperties` (на любой глубине) — только `x-php-type` (+ ключи объявления, если схема становится классом/enum). Контексты закрыты: `checkClass`/`checkAlias`/`checkProperty`. `x-enum-descriptions` в ядре нет.
- Цикл обязательных class-typed свойств (A.b: B, B.a: A) → warning на каждом свойстве цикла (`RequiredCycles`, после построения всех классов).
- `exclusiveMinimum: PHP_INT_MAX` / `exclusiveMaximum: PHP_INT_MIN` → warning, граница игнорируется.
- `Schema::requireProperty()` — для имён из `propertyNames()`; иное имя — `InvalidModel` (ошибка кода, не ввода).

## Этап 4a
- Enum: значения string или int одного типа; `null` среди значений или `type: [T, "null"]` → nullable-свойство. Имена case — UPPER_SNAKE из значения (`in-progress`→`IN_PROGRESS`, `inProgress`→`IN_PROGRESS`, `1`→`VALUE_1`, `-1`→`VALUE_MINUS_1`, `class`→`CLASS_`, ведущая цифра → `_`). Совпадение имён — ошибка; дубликат значения — warning. `x-enum-descriptions` — map значение→описание (ключи проверяются).
- `additionalProperties: <schema>`: объект без `properties` → `array<array-key, T>` (алиас), с `properties` → доп. свойство `$additionalProperties` (wire name `additionalProperties`, default `[]`); конфликт имени — ошибка.
- Инлайн-объекты/enum в свойствах классов (и в `items` — суффикс `Item`) → объявления `<Parent><Property>`; `x-php-class-name` на инлайн-схеме переопределяет; коллизия — ошибка, свойство молча `mixed` (abandoned). Инлайн-схемы вне свойств классов (items алиаса и т. п.) не генерируются: объект — ошибка, enum — warning и базовый тип.
- После ревью 4a: `$ref` на nullable-класс (`type: [object, null]`) даёт nullable-тип (как и для enum). Имя инлайн-класса строится из wire name свойства (не из `x-php-name`); нет пригодных символов — нужен `x-php-class-name`, иначе ошибка. Инлайн-схемы в `additionalProperties` тоже выносятся: значения map-свойства → `<Parent><Property>Value`, `additionalProperties` класса → `<Parent>AdditionalProperty`. Схема, уже объявленная под своим именем (цель `$ref` внутрь свойства), повторно не выносится.
- Enum: значения только из bool/float/null → не enum (warning, базовый тип); объект с `properties` + `enum` → класс. `""` → case `EMPTY`; `PHP_INT_MIN` → `VALUE_MINUS_9223372036854775808`; `type: number` допустим для целых значений; `x-enum-descriptions` списком (JSON так декодирует map с ключами 0..n-1; openapi-generator так пишет позиционные описания) принимается, только если в каждой позиции N стоит значение enum N (позиции — все не-null значения, дубли включительно, как у openapi-generator) — иначе ошибка неоднозначности, описания не применяются. Map `{"0":…,"1":…}` с ключами по порядку неотличим от списка. Все проблемы enum сообщаются разом.
- Ключи объявления (`x-php-class-name`, `x-dto-mutable`, `x-enum-descriptions`) на свойстве/items допустимы только если схема становится классом или enum, иначе warning «no effect».

## Этап 4b — композиция
- `allOf` — класс, только если есть свои `properties`, ≥2 объектных члена (`$ref` или с `properties`) или один инлайн-объект. `allOf: [$ref X]` (+ description/nullable) — обёртка-алиас X. Не-объектный `allOf`: ровно один типизированный член → его тип, ни одного → свой тип схемы, несколько → ошибка. `allOf` вместе с `oneOf`/`anyOf` → ошибка.
- Стратегия: `x-php-all-of` (`extends`|`merge`, иное → ошибка, берётся конфиг) или `dto.allOfStrategy`. `extends` — ровно один член-`$ref` на сгенерированный класс, остальное (инлайн-члены + свои `properties`) — собственные свойства. Иначе `merge`: все члены рекурсивно (через их `allOf`, `$ref` — до конца) + свои; `required` — объединение по всем частям. Повтор wire-имени с тем же типом — сливается молча, с другим — ошибка (§10). Член-не-объект (алиас, enum, union без discriminator) → ошибка; цикл `allOf` при merge → ошибка; неразрешённый `$ref`-член пропускается (ошибку дал загрузчик).
- Инлайн-объекты частей, пришедших через `$ref`, выносит класс самой той схемы (`Composition::ownParts`): `Kitten` (merge `Cat`+`Pet`) использует `CatToy`/`PetOwner`, не создаёт своих.
- `oneOf`/`anyOf` + discriminator на компоненте → abstract-база; варианты — только `$ref` на сгенерированные классы (иначе ошибка). Mapping: явный (`discriminator.mapping`; цель не среди вариантов → ошибка), остальным — имя схемы. Общие свойства — равные во всех вариантах (имя, wire, тип, required, default); при одном варианте общих нет; свойства, равные собственным свойствам базы, у вариантов убираются молча. Вариант с другим родителем / в двух объединениях / сама база → ошибка. Классический приём `Pet{oneOf:[Cat]}` + `Cat{allOf:[Pet,…]}` — допустим (тот же родитель).
- Инлайн `oneOf`/`anyOf` (с discriminator или без) и именованный без discriminator → union-тип: `null`-член и nullable-члены делают union nullable, член неизвестного типа (`{}`) → весь `mixed`, совпадающие члены схлопываются (`UnionType::of`). `properties` рядом с `oneOf` без discriminator → класс из `properties` + warning; `oneOf` и `anyOf` вместе → один union + warning (он шире схемы).
- Иерархия: класс, который кто-то расширяет, — `OPEN` (не final), discriminated — `ABSTRACT`; цикл наследования → ошибка, родитель снимается; разная mutability родителя и наследника → ошибка; свойство наследника с тем же wire-именем или PHP-именем (без регистра), что у предка → ошибка. `RequiredCycles` учитывает унаследованные свойства.
- После ревью 4b: `allOf` + `oneOf`/`anyOf` у любой схемы источника — ошибка (даже без ссылок на неё). Член `allOf` с одним `required` (или свои `required`) делает схему классом; `required` на свойство родителя при extends → warning (extends не ужесточает родителя, нужен merge). Явный `x-php-all-of: extends` без ровно одного класса-родителя → warning и merge. Класс за обёрткой `allOf: [$ref X]` находится и для extends, и для вариантов (`ClassLookup`).
- Merge: свойство, исключённое `x-php-skip` хоть в одном члене, исключено; другое PHP-имя или default у повторного wire-имени → ошибка.
- Discriminator без `oneOf`/`anyOf` на классе, который именованные схемы расширяют через `allOf` (Swagger-2-полиморфизм) → abstract-база с mapping (явный, иначе имя схемы-наследника); общие свойства в этом случае не переносятся. Без наследников — warning и игнор. Инлайн-наследники в mapping не входят.
- Варианты: повтор одного класса → warning, считается один раз; вариант, чьё имя mapping отдал другой схеме, → warning (значения нет). Вложенные discriminated-базы делят общие свойства от листьев к корню — результат не зависит от порядка схем.
- После повторного ревью 4b: проверка «`allOf` + `oneOf`/`anyOf`» только для схем, которые могут быть объектом (`SchemaShape::mayBeObject`): `x-php-type` по-прежнему обходит неподдержанную композицию; `oneOf`/`anyOf` без типизированных членов (паттерны и т. п.) у скаляра — ограничения, тип берётся из схемы. Warning о `required` на свойство родителя — только если свойство есть у предков (вся цепочка) и ещё не обязательно там; неизвестные имена молчат, как у обычных классов. Default при merge сравнивается в JSON-форме (`1` и `1.0` числа — одно). Swagger-2-база получает в mapping всех именованных потомков (транзитивно). Подкласс через `allOf` у базы с `oneOf`-списком, не попавший в варианты, → warning. Вариант без свойства-дискриминатора (с учётом унаследованных) → warning.
- После третьего ревью 4b: член union с `properties` (без `type`) считается типизированным, поэтому инлайн-объекты в `oneOf` снова дают ошибку «inline object is not generated». Ограничивающий член union (паттерн и т. п.) у схемы со своим `type` даёт её собственный тип: `{type: string, anyOf: [{pattern}, {type: integer}]}` → `string|int`. Не-объектная схема с `allOf` и типизированным union → union + warning, что `allOf` не учтён. Вариант из `oneOf`, который уже потомок базы через другой вариант (`Dog: allOf [Cat]`, `Pet: oneOf [Cat, Dog]`), допустим. Warning о подклассе вне вариантов — только для прямых наследников базы. Swagger-2-база без свойства-дискриминатора даёт один warning на базе, а не на каждом подклассе.

## Этап 5b — аннотации и verifyClasses

- `metadata: annotations` (по умолчанию на 7.4, `MetadataMode::defaultFor`) выводит те же `AttributeModel` строками Doctrine в docblock класса (после `@deprecated`) и свойства:
  - `@Name(key=value)`; один позиционный аргумент — голым значением, несколько — `value={a, b}`;
  - строки: `"` удваивается, перевод строки → `\n`, `*/` → `*\/`;
  - list `{a, b}`, map `{"k"=v}`, `{new}` → вложенная `@Name(...)`;
  - строка длиннее 100 байт переносит аргументы.
- Import-алиасы проверяются при любом `metadata`, кроме `none`.
- `AttributeRules::admitted` при `annotations` (в каждом списке аргументов: атрибута и каждого вложенного `new`):
  - позиционный аргумент вместе с именованным `value` — атрибут отбрасывается, strict → error, иначе warning;
  - больше одного позиционного — warning («collects them into one list under "value"»);
  - строка (или ключ map) с `\r`, `\n` или `*/` — warning о замене.
- В аннотациях `{class}` и класс `{const}` пишутся как `\FQCN`.
- `verifyClasses` (Enrich, только если metadata ≠ none):
  - для каждого выводимого атрибута сначала аргументы в порядке обхода (у `new` — класс, затем его аргументы), затем сам класс атрибута;
  - ошибки ставятся на location схемы свойства или класса; сначала свойства, потом класс;
  - сообщения: `Attribute class X does not exist.`, `Class X, used by attribute A, does not exist.`, `Constant X::C|C, used by attribute A, does not exist.`

## Этап 5a — атрибуты
- `x-php-attributes` (у класса и свойства): список `{class, args?}`; `args` map → именованные, list → позиционные; значения: скаляр, list, map, маркеры `{const: 'A::B'|'FOO'}`, `{class: X}`, `{new: {class, args}}`, `{literal: {...}}` (map с единственным ключом-маркером — всегда маркер). Ошибка грамматики → error на точном месте, атрибут пропускается, остальные остаются.
- `attributeAliases`: ключ `x-…` вне `x-php-`/`x-dto-` и не ключ ядра (`x-enum-descriptions`), значение `{class, args?}` (иное — ошибка конфига). У схемы/свойства ключ алиаса даёт атрибут по шаблону: строка ровно `{value}` / `{value.key}` — значение с типом; плейсхолдер внутри текста — строковая подстановка (bool → `true`/`false`, массив/null → ошибка); нет ключа → ошибка. Порядок: сначала `x-php-attributes`, затем алиасы в порядке конфига. Ключ алиаса в `items`/`additionalProperties`/у алиаса-схемы → warning «no effect».
- Цель: `metadata: attributes` — `new` в аргументах ниже PHP 8.1 → strict: ошибка, иначе warning и атрибут отбрасывается; `none` — атрибуты остаются в IR, emitter их не выводит; `annotations` — пока как `none` (этап 5b). Два `ImportAlias` с одним алиасом и разными namespace в одном классе → ошибка.
- После ревью 5a: `x-php-attributes`/алиасы инлайн-объекта относятся к свойству (у вынесенного класса `ClassContext::isInline()`, CustomAttributes их не повторяет); у `items`-объекта — warning «no effect» и атрибутов нет. У enum `x-php-attributes` и ключи алиасов — warning «no effect» (`checkEnum`). Ключи `x-*` во встроенных частях `allOf` проверяются: ключи ядра там — «no effect», неизвестные `x-php-*` — ошибка. `new` в аргументах ниже 8.1 теперь всегда отбрасывает атрибут (strict — с ошибкой), CustomAttributes сообщает точное место (`…/x-php-attributes/<i>`, `…/<alias>`). Ошибки грамматики аргументов (позиционный после именованного, `{const: X::class}` → «use {class: X}») — на месте `args`/`const`. Import-алиасы сравниваются без учёта регистра; проверка — только при `metadata: attributes`; при `annotations` до 5b — warning на класс.
